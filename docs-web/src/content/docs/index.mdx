## Why yarcl exists

The same production bug keeps showing up under different names: a feature flag typo that silently disables a paywall, a translation key that renders a blank label, a component variant that was renamed in the design system but still referenced in code. Each one looks different. Structurally, they're identical: **code assumes a configuration key exists, and nothing enforces that it does.**

Component libraries have the same problem in a quieter form. The library decides that buttons come in `sm`, `md` and `lg`, and your design system has to conform. Your options are all bad:

- **Hardcoded unions** fit one team and nobody else.
- **`string` props** accept `"meduim"` and `"gigantic"` without complaint.
- **Generics** reflect whatever the caller passes instead of validating it.
- **A hand-written list of types** next to the real values drifts the moment someone adds a size.

The library can't know which values are valid. That's the consumer's decision. So yarcl moves the contract to where the decision is made: **your config defines the design system, and the library derives its API from it.**

## The injection point

Everything hangs on one import inside the library:

```ts
// inside yarcl
import type config from '@yarcl/config';

export type Size = keyof (typeof config)['sizes'];
export type Color = keyof (typeof config)['colors'];
```

`@yarcl/config` isn't a real package. It's an injection point that two tools resolve to **your** file:

```ts title="vite.config.ts"
plugins: [yarcl({ config: 'src/yarcl.config.ts' })] // runtime values and generated CSS
```

```json title="tsconfig.json"
"paths": { "@yarcl/config": ["./src/yarcl.config.ts"] } // types
```

It's dependency injection at the type level. The library is compiled against your config, so its props accept exactly your keys, its components render your values, and the build generates CSS for them. There's one source of truth, and if the wiring is missing you get a loud error, not silently wrong defaults. [Why an alias and not module augmentation or codegen?](/reference/architecture/)
